# CongSpeak 桌面 TeamSpeak 客户端实施计划

更新日期：2026-11-17。状态：已有 0.2 音频原型与 0.3 常用交互测试版；功能范围已按用户要求扩展，当前总范围以 [TS3 功能对齐表](TS3-PARITY.md) 为准。本文原首版范围及工期仅保留作早期计划，不再代表完整对齐范围。

## 1. 目标与范围

构建 Windows、macOS、Linux 三端共享核心的 TeamSpeak 3 客户端，能够连接真实 TS3 服务器，与官方客户端进行稳定语音和文字交流，并提供降噪、回声消除、自动增益、语音激活及按键讲话。

用户已确定：首批只做桌面三端；音频处理是首版核心能力。本文的框架、版本范围、发布形式是建议实施基线，技术验证后再冻结。

首版优先服务日常频道语音用户。移动端、浏览器端、官方云服务集成、完整服务器管理、插件生态及游戏内覆盖层不进入首版。

### 首批验证矩阵

| 平台 | 建议首发基线 | 必测环境 |
| --- | --- | --- |
| Windows | Windows 11 x64 | 普通桌面、游戏前台、不同权限窗口、WASAPI、USB/蓝牙设备 |
| macOS | macOS 14.2+，Apple Silicon 与 Intel | 麦克风授权、快捷键权限、CoreAudio、休眠唤醒 |
| Linux | Ubuntu 24.04 LTS x64 为正式基线；Fedora 稳定版为扩展验证 | GNOME/KDE、X11/Wayland、PipeWire/PulseAudio 路径 |

以上系统下限必须与最终固定的 Tauri、CPAL 和原生依赖版本核对。Windows 10、旧版 macOS、Linux ARM64 在明确需求后扩展，不先承诺支持。Linux 不承诺覆盖所有发行版和桌面组合；发布时明确认证矩阵。

## 2. tsclientlib 接入判断

可复用：TS3 协议连接与加密、身份、频道/用户事件、文字命令、音频包收发、Opus 接收解码与抖动缓冲、文件传输接口。

需要自行实现：设备管理、重采样、降噪、回声消除、自动增益、语音激活、按键讲话、混音策略、桌面集成、配置与凭据管理、安装更新。

重要约束：

- 当前接收音频实现只支持 Opus；首版认证 Opus Voice/Music 频道，其他编码需检测并明确提示。若目标服务器大量使用其他编码，须在第一阶段调整范围。
- 当前源码存在自动重连能力，README 的相关表述已经过时；实现以固定版本源码与实测为准。
- 连接取消和终止错误的行为需回归 Issue #43，不能直接把连接示例当成可交付生命周期实现。
- 固定上游 commit、Rust 工具链及锁文件，禁止发布构建跟随浮动 master。
- 优先通过适配层补足产品逻辑；确需修改协议实现时使用维护分支，保留最小补丁和对应回归用例。

## 3. 技术基线与模块边界

推荐：Tauri 2 + React + TypeScript + Vite；Rust + Tokio；tsclientlib；CPAL；WebRTC Audio Processing Module（APM）。RNNoise 作为另一降噪后端，经过效果和构建验证后纳入首版。

首版不依赖自建业务服务器。连接、处理音频、身份和配置均在用户设备本地完成。

```text
apps/desktop/                 React 界面、Tauri 壳、能力配置与打包
crates/core/                  业务模型、会话管理、状态机、命令与事件
crates/teamspeak/             tsclientlib 适配、协议错误映射、版本隔离
crates/audio/                 音频设备、缓冲、重采样、DSP、编解码和混音
crates/platform/              全局快捷键、托盘、通知、系统凭据
crates/storage/               配置、收藏、历史、数据迁移
tests/interop/                与真实服务器及官方客户端的互通场景
docs/                        架构决策、兼容矩阵、测试方法、发布说明
```

模块数量可随首个原型简化，但职责边界保留。核心 Rust crate 不依赖 Tauri，使未来移动端可以复用业务、协议与音频处理。

### 线程、状态与 IPC

- 一个会话任务独占一个协议连接，通过有界命令队列接收操作，持续驱动协议事件。
- 音频设备回调仅做必要的数据搬运、格式转换和缓冲访问；复杂 DSP、编解码及网络操作交由工作线程/任务。
- 音频回调不执行磁盘 I/O、不等待网络、不持有长时间锁；缓冲有上限，队列拥塞时丢弃过时音频并计数。
- PCM 和编码音频留在 Rust；前端通过命令发起操作，通过事件接收状态、文本、发言与降频后的电平信息。
- Rust 是连接和频道状态的权威来源；前端维护展示投影，通过快照及带会话代次/序号的增量事件同步。
- 命令带请求 ID，区分“已提交”和“服务器确认成功”；权限不足、频道密码错误等返回可展示错误。
- 重连时更新会话代次并重建快照，避免旧连接事件和消息响应污染新状态。
- 前端热刷新、窗口隐藏或托盘运行不影响协议与音频任务。

## 4. 音频引擎

### 4.1 处理链路

```text
发送：采集 → 格式归一/重采样 → 回声消除/降噪/增益处理 → 发言门控 → Opus → 协议发送
接收：协议包 → 每人缓冲与解码 → 个人音量 → 混音/限幅 → 输出重采样 → 播放
参考：本客户端实际输出的混音信号 → AEC 参考输入
```

处理层以 48 kHz 为首选内部格式；设备按其支持的格式打开，不强行假定所有设备都支持固定采样率、声道和回调大小。使用帧累积器适配硬件回调、APM 约 10 ms 帧及首版默认 Opus 20 ms 帧；48 kHz 单声道分别为 480 和 960 个样本。

遵循频道编码与质量设置，验证频道切换或服务器修改编码时的重配置。Opus Voice/Music 根据实际频道模式处理，立体声和单声道做明确策略。

### 4.2 音频处理模式

| 设置 | 建议行为 | 验收重点 |
| --- | --- | --- |
| 降噪关闭 | 跳过降噪，其他功能独立控制 | 便于对照试听及使用外部处理设备 |
| 标准降噪 | WebRTC APM NS，提供适度强度配置 | 风扇、空调、底噪；避免吞字 |
| AI 降噪 | RNNoise，效果验证通过后提供 | 键盘、环境声与人声保真权衡 |
| 回声消除 | WebRTC APM AEC，可独立开关 | 扬声器外放、双向同时讲话 |
| 自动增益 | WebRTC APM AGC，可独立开关 | 远近说话、不削波、不明显放大静音底噪 |
| 发言方式 | 按键讲话、语音激活、持续发送 | 不漏首字、不长时间悬挂发言状态 |

首版先以标准降噪打通完整链路，再加入 RNNoise。RNNoise 不与 APM NS 默认叠加；组合时确定 AEC、RNNoise、AGC 的调用顺序和数据格式，避免前后处理互相干扰。APM/RNNoise 使用原生库或经验证的 Rust 绑定，冻结版本和构建方式，不预先认定现成绑定能够满足三端。

AEC 必须使用接近实际扬声器输出的参考音频，处理播放音量、延迟估计、设备切换和采播时钟差。首版保证本客户端通话的回声处理；其他应用声音的消除另行评估，不默认依赖全系统回环采集。

PTT/VAD 控制发送门控，避免频繁关闭设备和重置 DSP。切换静音、频道和设备时清除过时发送帧，确保不会把静音期间的声音延迟发出；按协议正确结束发言状态。

### 4.3 设备与语音激活

- 枚举、选择及记住输入/输出设备，支持“跟随系统默认设备”。
- 处理未授权、无设备、设备被占用、设备拔插、默认设备变化与流失效。
- 设备丢失后明确通知并按用户策略恢复；避免静默切换到用户不预期的麦克风。
- VAD 具备可调灵敏度、短预留音频和结束延迟，减少漏首字及句尾截断。
- 支持输入增益、总输出音量、个人音量、麦克风电平与处理后试听。
- 蓝牙耳机分别测试播放和双向通话模式，对音质/设备模式变化给出可理解反馈。

## 5. 协议、身份与会话

### 连接状态机

```text
未连接 → 地址解析 → 身份准备/等级提升 → 握手 → 同步频道与用户 → 已连接
已连接 → 临时中断 → 重连 → 重新同步 → 已连接
任一阶段 → 用户取消/终止错误 → 清理 → 未连接或失败
```

- 支持地址、端口、昵称、服务器密码和默认频道/频道密码；验证库提供的域名解析路径。
- 身份首次创建后持久化，安全等级提升可展示进度并取消，不能每次启动生成新身份。
- 支持多个本地身份、显式选择与删除；验证官方身份导入/导出格式后实现兼容及加密备份。
- 保存并核对服务器身份；身份变化时由用户决定是否信任，不能自动覆盖。
- 支持用户手动断开、取消连接；退出时进行有界时间的清理，避免残留后台连接。
- 把库内重连与应用级重连职责分开：库负责其支持的临时重连，应用负责网络恢复/唤醒触发和终止后的重建，避免两个循环重复连接。
- 重试设退避和抖动，提供停止操作；被踢、封禁、错误密码等终止原因不无条件重试。
- 重连后同步频道和静音状态；不自动重发结果不明的聊天消息或管理命令。
- 数据模型从第一版包含会话 ID；首版只开放一个活动连接，多服务器同时在线留到后续。

## 7. 三端桌面适配

### 快捷键与 PTT

抽象统一的按下/释放事件，处理重复按键、快捷键冲突、重绑定及退出释放。PTT 由原生侧直接改变发送门控，避免依赖前端焦点或响应速度。休眠、会话锁定、设备/权限异常时清除按下状态，避免卡麦。

Windows/macOS/X11 先验证现有快捷键实现。Wayland 必须验证 GlobalShortcuts Portal 或目标桌面提供的方案及按下/释放语义；常用 global-hotkey 库当前只声明 Linux X11 支持。未经验证不能宣传 Wayland 全局 PTT 与其他端一致。对不支持的桌面明确显示能力状态，提供窗口内 PTT、VAD 和切换发言模式；若完整 Wayland PTT 是发布硬要求，则其验证失败会阻塞发布。

### 桌面行为与发布形式

- Windows：托盘、通知、单实例、安装卸载；首选 NSIS 安装包，签名与更新联调。
- macOS：托盘/菜单栏、权限说明、签名与公证；Apple Silicon/Intel 分架构包或经验证的通用包。
- Linux：托盘差异、WebKit/系统依赖、音频与 Portal；先发布 deb，验证 AppImage，Flatpak 后续评估。
- 三端验证后台通话、最小化、关闭窗口进入托盘、显式退出及休眠恢复。
- 自动更新使用签名清单/包并验证失败恢复；平台签名证书与发布账户是对外发布依赖，可先用内部测试包推进。

## 8. 数据、安全与诊断

- 普通设置/收藏优先使用带 schema 版本的本地配置；聊天历史启用后使用 SQLite，并提供清理和保留期。
- 身份私钥、保存的密码通过专门安全存储层保存；优先使用系统凭据设施，确认大小限制及 Linux 无 Secret Service 时的行为。不可静默退回明文。
- 服务器/用户文本、格式化描述、图片和链接按不可信输入处理，限制资源大小；不执行远端脚本或把服务器内容直接注入 HTML。
- Tauri IPC 权限按功能最小开放，限制外链与文件访问范围。
- 默认不记录 PCM，不持久化私钥、密码和敏感协议包；诊断日志脱敏并轮转。
- 提供本地诊断：连接原因、丢包、抖动、音频队列积压、设备错误、音频回调欠载和处理耗时。
- 发布前核对实际依赖锁文件、许可证及漏洞扫描结果；保留第三方许可证与所需声明。官方商标、服务和资源授权另行确认，不把开源库许可等同于官方资源使用许可。

## 9. 开发阶段、交付物与退出条件

### M0：技术验证，约 1–2 周

任务：固定上游版本；建立三端最小构建；做无完整 UI 的连接/语音工具；连接测试服务器并与官方客户端互通；编译并调用 APM；验证 RNNoise 构建；验证全局 PTT 与 Wayland 路径；复现连接取消/终止错误问题；核对系统最低版本与原生依赖。

交付：可运行原型、三端构建记录、协议/音频问题清单、依赖固定方案、系统与 PTT 能力矩阵。

退出条件：三端真实收发语音；至少一台机器验证 APM 处理链与外放 AEC；三端 DSP 构建可行；取消/终止连接有可行修复路径。重大问题在此调整技术栈或范围，不带着未知风险开发完整 UI。

### M1：工程与核心状态，约 1 周

任务：建立目录、格式检查与 CI；定义业务命令/事件；实现会话状态机、身份与收藏存储、错误模型、最小 Tauri 界面及前后端同步。

交付：可连接/断开、保存身份和收藏的应用骨架。

退出条件：重复连接/取消/断开不产生重复任务；窗口刷新可恢复当前快照；敏感数据不出现在前端事件和日志中。

### M2：可用客户端，约 2 周

任务：频道树、用户、频道切换、聊天、设备选择、基础 Opus 收发、多人混音、静音、原生 PTT 与发言状态。

交付：可日常加入频道并通话的内部 Alpha。

退出条件：与官方客户端文字和语音互通；权限/密码错误明确；频道切换正确；PTT 释放后停止发送且不残留缓存语音。

### M3：音频质量，约 2–3 周

任务：APM NS/AEC/AGC、VAD、预留音频与结束延迟、麦克风试听、设备恢复、音频性能统计；比较 RNNoise；处理重采样、时钟差、限幅和队列上限。

交付：具有可配置音频处理的 Beta 候选版，附统一录音样本的处理前后对比。

退出条件：三端通过噪声、外放回声、双讲、远近讲话、拔插和蓝牙场景；处理耗时满足帧预算；RNNoise 达标则加入，否则明确列为未完成项，不用模式名称代替实现。

### M4：三端稳定性与体验，约 2 周

任务：断网重连、休眠恢复、托盘、通知、Wayland 适配、配置迁移、身份备份、长时间运行、安装依赖与干净机器验证。

交付：公开测试版、兼容矩阵与已知问题。

退出条件：每个平台通过 8 小时通话/空闲混合运行；重复网络与设备恢复无持续积压；认证环境安装后无需手工复制原生库。

### M5：发布，约 1–2 周

任务：回归、签名/公证、更新验证、许可证、使用文档、发布说明与诊断反馈流程。

交付：三端安装包、校验信息、更新通道及稳定版本说明。

退出条件：无已知阻断连接、卡麦、泄露凭据、严重音频失真或无法安装的问题；更新成功与失败恢复均验证。

周期粗估：一名熟悉 Rust/前端的全职开发者，M0–M5 为 9–12 周，加 1–2 周缓冲，总计约 10–14 周。APM 原生构建、Wayland PTT、上游修复和签名条件可能改变周期；M0 后重新估算。音频算法调优与全部发行版兼容不能仅按 UI 工作量估计。

## 10. 测试与质量门槛

| 类别 | 场景 | 建议验收 |
| --- | --- | --- |
| 协议互通 | 密码、身份等级、频道订阅、聊天、权限、踢出/封禁、频道编码变化 | 与真实 TS3 服务器及官方客户端行为核对 |
| 生命周期 | 连续取消/连接/断开、终止错误、退出 | 无 panic、无重复任务，服务器席位在预期清理/超时内释放 |
| 基础音频 | 单人、至少 8 路输入混音、静音、个人音量 | 无明显削波、无串会话/旧频道音频、发言状态正确 |
| 延迟 | 固定硬件和网络环境端到端测量 | 初始目标良好局域网 P95 ≤ 200 ms，M0 建立基线后冻结 |
| DSP 性能 | APM/RNNoise 最低配置设备 | 10 ms 处理块耗时 P99 < 10 ms，并保留余量；记录总 CPU/内存 |
| 降噪 | 风扇、空调、键盘、安静人声、不同音量 | 统一样本 A/B 试听，记录噪声抑制及语音损伤；不只看降噪数值 |
| AEC/AGC/VAD | 外放双讲、近远音量、轻声、句首句尾 | 无持续明显回声、不抽吸、不明显吞字；主观与录音共同验收 |
| 弱网 | 注入 1%/3%/5% 丢包及抖动/乱序 | 不崩溃、不无限积压，网络恢复后回到正常延迟 |
| 恢复 | 断网、网络切换、服务器重启、休眠、拔插 | 正确恢复或明确报错，用户可停止重试 |
| 快捷键 | 后台、游戏、按住重绑定、锁屏、Wayland | 按下/释放可靠，异常不会持续发送 |
| 发布 | 干净系统安装/卸载、签名、更新、数据迁移 | 保留配置与身份，失败可恢复，权限说明清晰 |

测试分层：状态机、门控和重采样边界做单元测试；连接和权限做真实服务器集成测试；录音样本做离线 DSP 回归；真机负责音频、权限和快捷键；CI 负责格式、静态检查、核心测试与三端构建。自动化不能替代真实设备通话。

质量门槛是计划目标，当前尚无测试结果。测试服务器和官方客户端作为验收依赖准备，避免在公共服务器上执行压力或故障注入。

## 11. 优先风险及应对

| 风险 | 最早处理时间 | 应对 |
| --- | --- | --- |
| tsclientlib 生命周期问题 | M0 | 复现、封装/最小上游补丁、回归；保留替换适配层的空间 |
| APM/RNNoise 三端原生依赖 | M0 | 小型编译与处理验证，固定源码/工具链/绑定，验证发布包依赖 |
| Wayland 无可靠全局 PTT | M0 | 验证 Portal 与目标桌面；公布矩阵和降级；硬要求不满足则阻塞发布 |
| Opus 之外的频道编码 | M0 | 检测和用户提示；根据目标服务器决定是否补齐 |
| 音频设备格式与蓝牙差异 | M0/M3 | 能力协商、重采样、恢复策略与真实设备矩阵 |
| 降噪导致人声受损或 AEC 无效 | M3 | 可关闭/试听、固定样本、双讲测试，参考信号和延迟校准 |
| 打包成功但干净机器不能运行 | M0/M4 | 及早产出安装包，原生库随包/系统依赖明确 |
| 签名账户/证书未准备 | M1 起 | 内部包推进，正式发布前具备签名和更新密钥 |

## 12. 第一个具体工作包

1. 初始化 Rust workspace 与最小 Tauri/React 工程，固定工具链及依赖。
2. 实现独立 CLI：连接、读取频道/用户、发消息、主动断开和取消。
3. 在受控服务器上与官方客户端完成 Opus 双向音频。
4. 接入 APM，做关闭/开启降噪、AGC 和外放 AEC 的录音对照。
5. 三端产出原型安装包，验证原生依赖与基础权限。
6. 验证原生 PTT，单列 Wayland Portal 的按下/释放结果。
7. 输出 M0 报告，冻结支持矩阵、库版本、补丁与下一阶段工期。
