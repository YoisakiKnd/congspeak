# 0.2.0 音频测试版

日期：2026-11-17。已实现可运行的音频收发与设置；尚未完成 Windows/Linux 真机、官方客户端人声互通、回声/双讲音质及长时间稳定性验收。

## 使用

1. 使用 `releases/windows/CongSpeak-0.2.0-windows-x64.exe`（Windows x64，需要系统 WebView2）。这是语音版，0.1.0 仅支持协议功能。
2. 填写服务器、昵称和可选默认频道后连接。
3. 打开右下角音频设置，刷新并选择麦克风和耳机；支持跟随系统默认设备。
4. 先测试扬声器，再佩戴耳机做麦克风试听。测试会应用设置；麦克风试听只在本机播放，期间停止网络发言。
5. 应用并保存，关闭面板，点击麦克风图标解除静音。默认按 F8 或按住界面发言按钮讲话，可改 F9–F12。
6. 可选语音激活或持续发送。语音激活阈值越高越不容易触发，含约 250 ms 句尾保留和短预留帧。

音频设置保存到系统应用配置目录的 `audio.json`，包含设备、增益、音量、处理模式、发言方式和快捷键。每次启动强制麦克风静音，不自动恢复上次的开放麦克风状态。耳机静音同时阻止发送。配置保存失败和快捷键冲突会明确提示；设置可能已应用，需要查看提示。

## 实现

- Rust 专用音频线程，CPAL 设备回调通过有界无锁环形缓冲传递 PCM。
- 控制命令与网络音频包使用独立队列，避免大量接收音频阻塞停止/静音。
- 设备优先协商 48 kHz 浮点格式；否则使用设备默认格式并进行连续线性重采样。支持常见整数/浮点采样格式及输入单声道混合。
- 网络接收采用 tsclientlib 的每用户抖动缓冲与 Opus 解码，最多 64 路解码队列；混音限幅后送到输出设备。
- 输出设备实际消费的信号回送 AEC 参考输入，避免仅引用预混音或尚未播放的音频。
- 实时声音处理使用 Sonora 0.3.0（WebRTC APM 的纯 Rust 移植）。标准模式启用 NS，可选 AEC 和 AGC2；RNNoise 模式使用 nnnoiseless，关闭 APM NS，顺序为 AEC → RNNoise → 独立 AGC 阶段。
- Opus 使用 48 kHz、单声道、20 ms 编码帧；根据频道 Opus Voice/Music 及质量调整码率。Opus Music 首版发送仍为单声道。
- PTT、语音激活、持续发送统一进入发送门控；静音、试听、服务器权限和连接状态均可阻止发送。
- 发言键释放、设置改变和会话变化更新音频代次；旧代次或超过 100 ms 的编码帧不发送。静音/设置切换发送结束包并清除旧缓冲。
- 原生全局按键通过 Tauri 插件接入；界面按钮支持鼠标、触屏和空格/回车。单次原生长按设置 120 秒上限。
- 设备流异常时显示错误并周期重试；指定设备消失时不静默换用其他麦克风，默认设备模式检查系统变化。
- 接收/发送权限根据当前协议状态查询；等待自身用户条目建立后才同步设备标志，防止初始服务器快照覆盖本地更新。
- macOS 包包含麦克风用途声明，最低系统版本设置为 14.2。

## 验证

本机：macOS Apple Silicon。

| 检查 | 已观测结果 |
| --- | --- |
| 核心/音频单元测试 | 7 项通过：过期快照、输入校验、帧累积、重采样连续性、RNNoise 静音、发言门控、DSP 与 Opus 编解码 |
| 严格静态检查 | 桌面、协议、CLI、音频及所有 example 的 Clippy `-D warnings` 通过 |
| 前端 | TypeScript 与 Vite 构建通过 |
| 实际设备播放 | 合成 Opus 包经抖动缓冲、混音后送入真实 CPAL 输出，RMS 峰值约 0.0172 |
| 服务器语音转发 | 两个临时协议客户端在授权频道交换 25 个合成 Opus 包，解码 RMS 约 0.0147 |
| 应用会话接收播放 | TS3 → Session → Opus 解码/混音 → CPAL 输出通过，麦克风保持关闭 |
| 本地采集 | 真麦克风 → DSP → Opus 有编码输出；不联网、不保存录音；PTT 释放后停止编码、静音后关闭采集流 |
| 原生设置界面 | 能显示真实设备、处理和发言选项，应用并保存显示成功，配置文件已检查 |
| Windows 包 | release MSVC x64 交叉编译成功；PE32+ GUI，导入检查没有额外 Opus/VC/WebView2Loader DLL |

服务器测试仅使用用户授权频道，检查频道无其他用户后才发送短合成音。没有发送本机环境声音、没有聊天消息、没有保存录音或把密码写入配置。网络测试使用临时身份。

音频 `example` 工具：

```sh
# 只播放合成音，验证真实输出；不打开麦克风。
cargo run -p congspeak-audio --example runtime_smoke --features runtime --release

# 短暂打开本机麦克风，验证采集、DSP、PTT 和静音；不联网、不保存录音。
cargo run -p congspeak-audio --example capture_smoke --features runtime --release
```

`voice_interop` 和 `session_receive` 从 stdin 读取 ConnectRequest JSON；需要明确指定有权测试的服务器和频道，不应在公共频道执行。

## 构建补丁

`vendor/audiopus_sys` 保留上游 0.2.2 的源文件和许可证，只修改构建脚本：兼容 CMake 4、静态 CRT、非 Windows 主机交叉编译 MSVC 时关闭旧 Opus 中不兼容 clang-cl 的 SSE4.1 路径，保留 x64/SSE2 基线。说明见其 `CONGSPEAK-PATCH.md`。

## 仍需验证或改进

- Windows 包已构建但没有 Windows 真机运行结果；Linux/Wayland 全局 PTT 仍有限制。
- 当前网络测试是同库客户端间的合成音频；与官方客户端真实人声的双向通话仍需人工验收。
- 真实 AEC 的外放回声抑制、双讲、蓝牙延迟、采播时钟差和语音保真尚未量化验证。麦克风本地试听会暂时禁用 AEC，避免试听本人的声音被消除。
- 当前使用线性重采样，尚无高质量抗混叠滤波；不同硬件的实际效果需测试。更高质量重采样、时钟漂移补偿与弱网调优后续实现。
- 不支持旧 Speex/CELT 频道；遇到非 Opus 编码提示不受支持。
- 全局按键目前只提供 F8–F12，尚未实现任意按键组合、鼠标侧键和 Wayland Portal。
- 设备和设置改变会重建音频流，可能产生短暂中断。
- 当前语音激活基于处理后的电平阈值与延迟门控，尚不是完整神经网络 VAD。

Windows 单文件仍需要系统 WebView2 Runtime；未签名，不属于正式稳定版。


## 0.3.1：Windows 开麦后对方无声排查

用户反馈 Windows 麦克风本地试听正常，对方听不到。现有默认模式为按键讲话，解除静音并不会自动发送；该反馈尚不能证明具体根因已经确定。

本次改动：

- 底栏直接显示和切换发言模式，区分解除静音、等待 PTT、语音激活阈值、离开/服务器条件及实际发送状态。
- 设置显示原始/处理后电平、发送/接收条件和包计数。发送数表示网络层接受提交，不是对端收听确认。
- 修复把 CPAL 的 Xrun、DeviceChanged、RealtimeDenied 等非致命通知当作流故障反复重建的问题。WASAPI 可以在采集不连续时发出 Xrun；此改动已覆盖回归测试，尚未在用户 Windows 设备实测。
- 按设备实际方向筛选麦克风和扬声器，防止 WASAPI 的输出端点回环配置被误列为麦克风。已保存的方向错误设备会明确报错，要求重新选择。

2026-11-17 验证：8 项核心/音频测试通过；桌面与所有 example 严格 Clippy、TypeScript/Vite 构建通过；Windows x64 单 EXE 已交叉构建并检查 PE / DLL 导入。

新增 `session_send` 完整链路测试，macOS 实机在授权且空闲的目标频道运行：实际 CPAL 采集 → 零输入增益 DSP → Opus → Session 发送 → TS3 → 第二临时客户端解码，提交 40 包、收到 40 包；未按 PTT 不发送，释放后停止，静音后关闭采集。输入在 DSP 前乘零，没有传输环境声音或保存录音。解码峰值约 0.0000611（有损编码的静音底噪，约 2 个 16-bit PCM 步长）。最初过严的逐样本静音断言已改成明确的 4 步长容差后完成验证。

## 0.3.2：通话中断后不再发送

用户确认故障模式为语音激活，且原始麦克风电平仍变化；尚未在 Windows 真机复现同一故障。实现与验证记录见 [STABILITY.md](STABILITY.md)。

已加入 DSP 错误/无效采样自动重建、设备回调停滞检测、采集积压保留最新声音、接收解码故障边界，以及保留连接的音频重启和最近约两分钟状态诊断。

macOS 实际设备持续故障测试（标称至少 150 秒）：注入一次确定可使旧解码队列越界的损坏包，并持续注入丢包、重复、突发/迟到包，周期性撤销再恢复发送条件。接收异常被捕获，后续采集继续编码 8,604 帧；显式重启音频后继续编码 91 帧。输入增益为零，无网络；测试日志中一次 Rust panic hook 输出是故意注入的接收异常，随后被接收边界捕获并恢复，程序最终 PASS。

14 项核心/音频测试、所有目标严格 Clippy、TypeScript/Vite 构建通过。授权服务器零增益发送测试收到 41/41 包。Windows 包为 `releases/windows/CongSpeak-0.3.2-windows-x64.exe`，未在 Windows 硬件运行该版本，不作为长期通话稳定性认证。
